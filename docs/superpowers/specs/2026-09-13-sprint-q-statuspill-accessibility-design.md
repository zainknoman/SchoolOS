## Decisions this spec makes so engineering doesn't have to guess

**`StatusPill.vue` ships exactly as originally scoped** — no redesign, since nothing about its
target usage has changed since 2026-09-07. Build it, swap the three named call sites, done.

**The segmented control becomes a real ARIA `radiogroup`/`radio` pattern**, not a re-skin with
`aria-label`s bolted onto existing buttons — `role="radiogroup"` on the `.segmented` container
(with an `aria-label` naming the student, e.g. `"Attendance for {name}"`), `role="radio"` +
`aria-checked` on each `.segment` button, and arrow-key (Left/Right) navigation moving focus between
the three options within one student's row — the standard accessible pattern for a same-row
mutually-exclusive choice, matching what a screen reader / keyboard user expects from a segmented
control anywhere else on the web.

**`TrendsSparkline`'s label gets richer context, not a rewrite of the component's rendering logic**:
change the label-generation `computed` to name the metric's unit and pair each value with its
corresponding day label from `props.labels`, e.g. `"Attendance percent by day: Mon 88%, Tue 95%,
Wed 82%..."` instead of the current bare `"Attendance: 88, 95, 82"`. This is a one-function change,
not a component redesign.

## Design

### 1. `StatusPill.vue`
```vue
<!-- staff-console/src/components/StatusPill.vue -->
<script setup lang="ts">
defineProps<{ tone: 'success' | 'warning' | 'critical' | 'info' | 'neutral'; label: string }>();
</script>
<template>
  <span class="status-pill" :class="`tone-${tone}`">{{ label }}</span>
</template>
```
Tone mapping per call site (locking the exact mapping so implementation doesn't re-derive it):
- `LeaveManagementView`: `pending → warning`, `approved → success`, `rejected → critical` (replaces
  the `.badge-pending/.badge-approved/.badge-rejected` classes named in the original spec).
- `FeeManagementView`'s ledger: `unpaid → neutral`, `partial → warning`, `paid → success`,
  `overdue → critical` (the exact mapping already written into the original shell-redesign spec).
- `AcademicSessionManagementView`: active/inactive session indicator — `isActive: true → success`,
  `false → neutral`.

### 2. Attendance segmented-control accessibility fix
`AttendanceView.vue`'s roster row (`:133-` today):
```html
<div class="segmented" role="radiogroup" :aria-label="`Attendance for ${student.name}`">
  <button
    type="button"
    role="radio"
    :aria-checked="statuses[student.id] === 'PRESENT'"
    :tabindex="statuses[student.id] === 'PRESENT' || !hasAnyChecked(student.id) ? 0 : -1"
    :data-testid="`status-${student.id}-present`"
    class="segment segment-present"
    :class="{ active: statuses[student.id] === 'PRESENT' }"
    @click="setStatus(student.id, 'PRESENT')"
    @keydown.right="focusNextSegment(student.id, 'PRESENT')"
    @keydown.left="focusPrevSegment(student.id, 'PRESENT')"
  >
    P
  </button>
  <!-- ABSENT, LATE siblings follow the same shape -->
</div>
```
`focusNextSegment`/`focusPrevSegment` move both the visual selection *and* DOM focus to the
adjacent segment button (standard roving-tabindex radiogroup behavior — only the checked/first
segment is in the Tab order; arrow keys move within the group). Applies identically to every
roster row, not just one.

### 3. `TrendsSparkline.vue` label fix
```ts
const accessibleLabel = computed(() =>
  props.series
    .map((s) =>
      `${s.label} by day: ` +
      s.values.map((v, i) => `${props.labels[i] ?? ''} ${v}${s.unit ?? ''}`).join(', '),
    )
    .join('. '),
);
```
Requires threading a `unit` (e.g. `'%'`, `' PKR'`) into each series object passed from
`AdminHomeView.vue` — confirm the exact prop shape `TrendsSparkline` currently accepts
(`labels`/`series`) before implementing; add `unit` as an optional field on each series entry,
defaulting to `''` so existing callers that don't pass it don't break.
