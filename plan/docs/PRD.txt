# PRODUCT REQUIREMENTS — SchoolOS Digital Platform
Generated: 2026-08-27  ·  Owner: The SchoolOS School (via user)

## 1. Overview
A replacement for The SchoolOS School's current two-vendor setup (an unpublished WebView-shell Android app
from one vendor, a separately-built website portal from another). One backend serves a Flutter parent
app and a role-gated Vue staff console (Teacher/Admin/Accounts), so parents and staff always see the
same data. Every screen exists to answer the parent's question: "What do I need to know about my child
today?" — in English and Urdu (RTL), on a mid/low-end Android phone with a weak connection.

## 2. Goals
- Parents can see timetable/attendance/diary/circulars/messages/fees for each of their children from one
  login, with data that matches across app and web.
- Staff (teacher/admin/accounts) can author attendance, diary, circulars, and manage fees from one
  console instead of two disconnected vendor back-offices.
- The app is store-published (Play Store, then App Store) under the school's own account — not
  sideloaded.
- Fee payment happens in-app (JazzCash/EasyPaisa), not voucher-view-only.

## 3. Scope (in)
- Auth (email/GR-number + password, JWT+refresh, RBAC), multi-child switcher.
- Calendar-based Timetable / Attendance / Diary (per SchoolDetails.txt's existing UX pattern).
- Circulars (school + section scope, read-tracking, attachments).
- Messages (scoped inbox: Parent ↔ Class Teacher / Admin / Accounts / Principal only).
- Fees (server-computed voucher, PDF, in-app JazzCash/EasyPaisa payment, payment history).
- Leave applications (submit/approve, reflects on attendance calendar).
- Push notifications with deep links; offline "last updated" caching.
- Staff console: teacher (attendance, diary, timetable, messages) + admin/accounts (CRUD, circulars,
  fee/voucher management, leave approval, complaint tracking).
- Data migration plan from the two existing vendor systems.

## 4. Non-goals (out)
Payroll, full accounting ERP, library, transport GPS, RFID/biometric attendance, canteen/wallet, AI
tutor or AI-generated summaries, complex LMS/e-content, online examinations, inventory/procurement/HR,
custom report builder, live gradebook (static report-card PDF instead), a separate parent web portal
(Phase 2), separate Teacher/Admin portal apps, campus-switching UI, WhatsApp integration (Phase 2
candidate), a public-website redesign (separate, lower-priority track).

## 5. Success criteria
- Parent logs in, sees only their authorized children, switches between them, and every screen updates.
- Calendar shows correct per-date timetable/attendance/diary; Urdu renders RTL, untranslated.
- Fee voucher is server-computed, payable in-app, downloadable as PDF, with payment history.
- Teacher can mark attendance + publish diary; Admin can publish circulars + manage fees/students.
- Pilot: ≥70% parent login rate within 2 weeks of a pilot-class rollout.
